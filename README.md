# MeetingApp — обработка встреч

Нативное macOS-приложение (SwiftUI): транскрибация видео/аудио, записей с YouTube и
видеозвонков (Zoom/Meet/Teams) через локальный [whisper.cpp](https://github.com/ggerganov/whisper.cpp),
саммари через Claude Code и сохранение в Заметки и/или Notion.

## Возможности

- Загрузка видео/аудио (drag & drop), ссылки на YouTube или готового `.txt`-транскрипта
- Запись голоса с микрофона
- **Автоопределение видеовстречи** (Zoom/Google Meet/MS Teams) по вкладке браузера
  (Safari/Chrome/Brave/Yandex) и по календарю (iCloud/Google/Exchange — любой источник,
  который видит macOS) — плавающее уведомление внизу экрана предлагает начать запись
- **Запись встречи**: системный звук (голоса собеседников) через ScreenCaptureKit +
  микрофон, сведённые в одну дорожку; отдельная вкладка «Записи встреч» со статусом
- Автоопределение языка (или ручной выбор) в whisper
- Подбор модели whisper под железо (RAM/CPU) с возможностью сменить вручную
- Автоустановка зависимостей: ffmpeg, whisper.cpp, yt-dlp, Claude Code (npm + вход в
  аккаунт прямо из приложения)
- Отдельные «Отмена» (пауза с сохранением прогресса) и «Удалить» (стирает насовсем)
- Прогресс текущего шага с оценкой оставшегося времени вместо лога (лог свёрнут по умолчанию)
- История с фильтром по статусу, разворачиваемые подробности ошибок
- Сохранение саммари в Заметки и/или в базу Notion «Саммари встреч»
- Если Claude Code недоступен (или саммари не из чего собрать) — обработка
  останавливается на шаге «Транскрипт готов», транскрипт не теряется, саммари можно
  запустить вручную позже из Истории

## Сборка

Требуется Xcode Command Line Tools (Swift 5.9+) и Homebrew.

```bash
cd MeetingApp
./build_app.sh
```

Скрипт собирает `.app`, подписывает его стабильным ad-hoc идентификатором
(`ru.sk.meetingapp` — важно для того, чтобы macOS не сбрасывала выданные разрешения
между пересборками: микрофон, автоматизация браузеров/Заметок, календарь, запись
экрана) и раскладывает shell-скрипты в `~/Встречи/scripts`. Готовое приложение
переносится в `/Applications` вручную.

## Разрешения macOS

Приложению отдельно нужны (каждое подтверждается системным диалогом при первом
использовании): микрофон, запись экрана (для звука встречи через ScreenCaptureKit —
видео не сохраняется), автоматизация Safari/Chrome/Brave/Yandex (чтение URL активной
вкладки) и Notes (сохранение саммари), полный доступ к календарю (поиск встреч).

## Дистрибуция

Приложение **не предназначено для Mac App Store**: оно ставит зависимости во время
выполнения через Homebrew/npm и скачивает аудио с YouTube — оба действия прямо запрещены
[App Review Guidelines](https://developer.apple.com/app-store/review/guidelines/)
(2.4.5 — запрет на скачивание/исполнение стороннего кода и установщиков вне Xcode;
5.2.3 — запрет на скачивание контента с YouTube без разрешения). Распространяется вне
App Store (прямой .app/.zip). Из духа гайдлайнов всё равно соблюдаются: честные
purpose-strings для каждого разрешения, явное согласие перед записью, никакой скрытой
передачи данных.

## Структура

```
MeetingApp/
├── Package.swift
├── build_app.sh                    # сборка + подпись + иконка + деплой скриптов
├── Resources/AppIcon.icns
├── Sources/MeetingApp/
│   ├── Models.swift                 # Job, стадии, распознавание ссылок YouTube/ВКС
│   ├── JobStore.swift                # вся бизнес-логика и пайплайн обработки
│   ├── Views.swift                   # SwiftUI-экраны
│   ├── AudioRecorder.swift           # запись микрофона (AVFoundation)
│   ├── SystemAudioRecorder.swift     # запись системного звука (ScreenCaptureKit)
│   ├── BrowserMeetingDetector.swift  # опрос браузеров через AppleScript
│   ├── CalendarMeetingDetector.swift # опрос календаря через EventKit
│   └── MeetingAlertPanelController.swift  # плавающее уведомление (NSPanel)
└── scripts/                         # shell-пайплайн: download → transcribe → summarize → mix
```

## CI и тестирование

`.github/workflows/build.yml` проверяет, что `swift build` проходит на каждый push.
**Автоматических тестов в проекте пока нет** — вся проверка до сих пор ручная: сборка,
переустановка в `/Applications`, прогон реального сценария (тестовое событие в
календаре, тестовая запись с микрофона и т.п.) с проверкой `history.json` и логов.
Для проекта такого размера с одним разработчиком это осознанный выбор скорости, но
часть логики уже вполне тестируема юнит-тестами без реального приложения — например,
`MeetingLinkDetector.firstMeetingLink`, `WhisperModelOption.recommended()`,
переходы `JobStage`. Если понадобится — можно добавить SPM test target
(`swift test`) под эти чистые функции; риск скорее в `JobStore`, где логика плотно
завязана на `Process`/`Timer`/системные фреймворки и просто так не мокается.
Релизная сборка (`build_app.sh`) запускается вручную, автодеплоя нет.
