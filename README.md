# MeetingApp — обработка встреч

Нативное macOS-приложение (SwiftUI): транскрибация видео/аудио, записей с YouTube и
видеозвонков (Zoom/Meet/Teams) через локальный [whisper.cpp](https://github.com/ggerganov/whisper.cpp),
саммари через Claude Code и сохранение в Заметки и/или Notion.

## Возможности

- Загрузка видео/аудио (drag & drop), ссылки на YouTube или готового `.txt`-транскрипта
- Запись голоса с микрофона
- **Автоопределение видеовстречи** (Zoom/Google Meet/MS Teams) по вкладке браузера
  (Safari/Chrome/Brave/Yandex) и по календарю (iCloud/Google/Exchange — любой источник,
  который видит macOS) — плавающее уведомление внизу экрана предлагает начать запись
- **Запись встречи**: системный звук (голоса собеседников) через ScreenCaptureKit +
  микрофон, сведённые в одну дорожку; отдельная вкладка «Записи встреч» со статусом
- Автоопределение языка (или ручной выбор) в whisper
- Подбор модели whisper под железо (RAM/CPU) с возможностью сменить вручную
- Автоустановка зависимостей: ffmpeg, whisper.cpp, yt-dlp, Claude Code (npm + вход в
  аккаунт прямо из приложения)
- Отдельные «Отмена» (пауза с сохранением прогресса) и «Удалить» (стирает насовсем)
- Прогресс текущего шага с оценкой оставшегося времени вместо лога (лог свёрнут по умолчанию)
- История с фильтром по статусу, разворачиваемые подробности ошибок
- Сохранение саммари в Заметки и/или в базу Notion «Саммари встреч»
- Если Claude Code недоступен (или саммари не из чего собрать) — обработка
  останавливается на шаге «Транскрипт готов», транскрипт не теряется, саммари можно
  запустить вручную позже из Истории

## Установка

Приложение раздаётся готовым бандлом: всё нужное, включая скрипты обработки, лежит
внутри `.app`. Собирать ничего не требуется.

### Что понадобится

- macOS 13 или новее, Apple Silicon или Intel
- [Homebrew](https://brew.sh) — через него приложение само поставит ffmpeg, whisper.cpp
  и yt-dlp
- Аккаунт [Claude](https://claude.ai) с подпиской, которая даёт Claude Code — им
  собирается саммари
- Около 4 ГБ на диске: 2,9 ГБ занимает модель распознавания, остальное — утилиты
- Интернет на первую установку. Дальше распознавание работает локально, без интернета;
  он нужен только для саммари и выгрузки в Notion

### Шаг 1. Скачать

Возьми `MeetingApp.zip` из раздела [Releases](../../releases) — это последняя
выпущенная версия.

### Шаг 2. Переложить в «Программы»

Распакуй двойным щелчком и перетащи `MeetingApp.app` в папку «Программы».

### Шаг 3. Открыть в первый раз

Приложение подписано самодельным сертификатом: Apple за него не ручается, поэтому
macOS при первом запуске откажется его открывать. Это ожидаемо, и обойти можно без
терминала:

1. Открой приложение двойным щелчком — появится предупреждение, нажми «Готово».
2. Зайди в **Системные настройки → Конфиденциальность и безопасность**.
3. Прокрути до раздела «Безопасность» — там будет строка про MeetingApp и кнопка
   **«Всё равно открыть»**. Нажми её и подтверди.
4. Дальше приложение открывается как обычное, предупреждение больше не появится.

Если macOS 14 или старше — достаточно щёлкнуть по приложению правой кнопкой и выбрать
«Открыть».

Предупреждения не будет вовсе, если принести приложение на флешке: метку «скачано из
интернета» вешает браузер, а не файл сам по себе.

### Шаг 4. Поставить компоненты

При первом запуске приложение покажет окно со списком того, чего не хватает, и кнопкой
установки. Нажми её и подожди: ffmpeg, whisper.cpp и yt-dlp ставятся через Homebrew,
модель распознавания (2,9 ГБ) скачивается, Claude Code ставится через npm и попросит
войти в твой аккаунт.

Проверить состояние позже можно в **Настройки → Обслуживание → Проверить компоненты**.

### Шаг 5. Разрешения macOS

Приложение запросит их само, по ходу работы. Каждое нужно для конкретной вещи:

| Разрешение | Зачем |
| --- | --- |
| Микрофон | записывать твой голос на встрече |
| Запись экрана | записывать голоса собеседников (пишется только звук, видео не сохраняется) |
| Календарь | находить встречи со ссылкой на видеозвонок и предлагать запись |
| Заметки | сохранять саммари в Заметки |
| Safari/Chrome | узнавать открытую встречу по вкладке браузера |

### Шаг 6. Настроить под себя

- **Настройки → Словарь**: аббревиатуры, названия систем, фамилии. Распознавание
  перестанет их коверкать, а саммари — расшифровывать наугад.
- **Настройки → Встречи**: если у вас своя платформа видеосвязи, добавь фрагмент её
  ссылки — тогда приложение будет узнавать и такие встречи.
- **Настройки → Интеграции**: токен Notion, если нужна выгрузка саммари туда. Берётся в
  Notion: Settings → Developer → Personal access tokens → New token, с доступом к нужной
  базе. Хранится в Связке ключей.

### Куда всё складывается

Записи, транскрипты и саммари лежат в `~/MeetingApp`. Из приложения никуда ничего не
уходит само: транскрибация идёт на твоём компьютере, саммари собирается твоим Claude
Code, а в Notion или Заметки саммари попадает только по нажатию кнопки.

## Сборка

Требуется Xcode Command Line Tools (Swift 5.9+) и Homebrew.

```bash
cd MeetingApp
./build_app.sh          # промышленная сборка
./build_app.sh --test   # тестовая сборка
```

Скрипт собирает `.app`, подписывает его и раскладывает shell-скрипты в папку
данных этой сборки. Готовое приложение переносится в `/Applications` вручную.

### Две сборки: тестовая и промышленная

Приложение обрабатывает реальные рабочие встречи, поэтому правки проверяются
на отдельной сборке и только потом попадают в ту, которой пользуются каждый день.

|                        | промышленная       | тестовая                |
|------------------------|--------------------|-------------------------|
| приложение             | `MeetingApp.app`   | `MeetingApp-Test.app`   |
| идентификатор          | `com.meetingapp.macos` | `com.meetingapp.macos.test` |
| данные и скрипты       | `~/MeetingApp`     | `~/MeetingApp-Test`     |
| настройки              | свои               | свои                    |
| разрешения macOS       | свои               | свои                    |

Папку данных задаёт ключ `MADataFolder` в `Info.plist`, приложение читает его при
запуске. Разные идентификаторы нужны не только чтобы сборки не путались в Dock:
macOS выдаёт разрешения (запись экрана, микрофон, календарь) именно по
идентификатору, поэтому тестовой сборке разрешения выдаются отдельно — один раз.

Все данные приложения лежат в одной папке с латинским именем: `models`,
`recordings`, `transcripts`, `processed`, `scripts` и `history.json`. Раньше они
были разбросаны по `~/Встречи` и `~/whisper-models`; при первом запуске новой
версии старая раскладка переезжает автоматически, пути в истории переписываются,
а рядом остаётся копия `history.json.before-migration`.

Модели весят гигабайты, поэтому тестовая сборка их себе не забирает: у неё
`models` — это ссылка на модели рабочей сборки.

### Выпуск и откат промышленной сборки

У рабочей сборки есть точки отката — такие же, как у тестовой. Их ставит сам
скрипт выпуска, чтобы это не держалось на памяти.

```bash
cd MeetingApp
./release_prod.sh            # собрать, установить и пометить выпуск
./release_prod.sh --dry-run  # посмотреть, что будет сделано
./rollback_prod.sh           # вернуться на предыдущий выпуск
./rollback_prod.sh --list    # показать доступные точки отката
```

Метки: `prod-current` — то, что стоит сейчас, `prod-previous` — предыдущий
выпуск, плюс `prod-<дата>` на каждый выпуск отдельно, чтобы можно было вернуться
не только на шаг назад.

Откат собирает приложение из помеченного коммита в отдельной рабочей копии и
подменяет только `/Applications/MeetingApp.app`. Текущая ветка, незакоммиченные
правки и папка с данными не трогаются: откат — это подмена приложения, а не
состояния разработки.

Оба скрипта отказываются работать, пока приложение занято распознаванием,
сбором саммари или выгрузкой: прерывать обработку реальной встречи нельзя.

### Процесс изменений

1. Работа идёт в ветке `dev`.
2. `./build_app.sh --test`, установка `MeetingApp-Test.app` в `/Applications`,
   проверка затронутых функций на реальном сценарии.
3. Только после успешной проверки — слияние `dev` в `main` и
   `./build_app.sh` с переустановкой промышленной сборки.

Настройки тестовой сборки можно засеять из рабочей (без пути к скриптам и без
сохранения в Заметки и Notion, чтобы тестовые прогоны не засоряли рабочие записи):

```bash
defaults export ru.sk.meetingapp - | defaults import ru.sk.meetingapp.test -
```

### Про подпись (важно для разрешений macOS)

При первом запуске на новой машине скрипт сам создаёт локальный самоподписанный
сертификат «MeetingApp Local Signing» в login-связке ключей — ничего делать
руками не нужно, платный Developer ID не требуется.

Зачем: у ad-hoc подписи (`codesign --sign -`) «designated requirement» — это
хэш конкретного бинарника:

```
designated => cdhash H"15413de..."
```

Любая пересборка меняет хэш, и для TCC это уже другое приложение: выданные
разрешения перестают действовать, хотя строка приложения в Системных настройках
остаётся и выглядит включённой (она привязана к bundle ID, а проверка идёт по
требованию). На практике это выглядит как «разрешение выдано, но запись экрана
не работает», сколько ни нажимай «Разрешить».

С сертификатом требование становится привязанным к идентификатору и сертификату
и от хэша не зависит:

```
designated => identifier "ru.sk.meetingapp" and certificate leaf = H"a6e99f8..."
```

Сертификат живёт 10 лет; если станет не нужен — удаляется через Связку ключей
(тогда сборка вернётся к ad-hoc и предупредит об этом).

## Языки интерфейса

Язык разработки — русский: строки написаны прямо в коде, и они же служат ключами
перевода. Английский перевод лежит в `MeetingApp/Resources/Localization/en.lproj/Localizable.strings`.

Чтобы добавить язык, скопируй эту папку в `<код языка>.lproj` и переведи значения —
сборка подхватит её сама и допишет язык в `Info.plist`. Строки без перевода
показываются по-русски, поэтому неполный перевод ничего не ломает.

Проверить перевод, не меняя язык системы:

```bash
open -a MeetingApp --args -AppleLanguages "(en)"
```

## Выгрузка в Notion

Приложение пишет саммари в Notion напрямую по API, своим токеном — без Claude и
без подключений claude.ai. Так получилось не от хорошей жизни: подключения
аккаунта claude.ai не достаются сессии `claude -p`, которую запускает
приложение, при этом claude завершался с нулевым кодом, ничего не сделав, и
выгрузка «успешно» заканчивалась ничем.

Что нужно настроить один раз:

1. Notion → Settings → **Developer** → Personal access tokens → **New token**.
2. При создании дать токену доступ к базе саммари — Notion показывает по API
   только то, что разрешено явно.
3. Настройки приложения → **Интеграции**: вставить токен и указать название базы.
   Токен хранится в Связке ключей macOS (служба `MeetingApp Notion API`),
   у тестовой и рабочей сборки он свой.

Базы приложение не создаёт: если базы с указанным именем нет или у токена нет к
ней доступа, выгрузка скажет об этом прямо, а подробности лягут в `export.log`
рядом с саммари.

Версия API зафиксирована на `2022-06-28`. Обновлять осознанно: с версии
`2025-09-03` страница создаётся не в базе, а в источнике данных, и тело запроса
меняется.

## Разрешения macOS

Приложению отдельно нужны (каждое подтверждается системным диалогом при первом
использовании): микрофон, запись экрана (для звука встречи через ScreenCaptureKit —
видео не сохраняется), автоматизация Safari/Chrome/Brave/Yandex (чтение URL активной
вкладки) и Notes (сохранение саммари), полный доступ к календарю (поиск встреч).

## Выложить новую версию для коллег

Приложение самодостаточно: скрипты лежат внутри `.app` и раскладываются в папку данных
при запуске, поэтому раздаётся один архив.

```bash
ditto -c -k --keepParent /Applications/MeetingApp.app ~/Desktop/MeetingApp.zip
```

Архив прикладывается к очередному релизу на GitHub — там же, где его берут по
инструкции из раздела «Установка».

Что **не** переносится и переноситься не должно: записи и саммари (`~/MeetingApp`),
токен Notion (он в Связке ключей) и настройки — в словаре и в списке своих платформ
ВКС лежат фамилии и внутренние адреса. Команду `defaults export` из раздела про
тестовую сборку на чужой машине не используй.

## Дистрибуция

Приложение **не предназначено для Mac App Store**: оно ставит зависимости во время
выполнения через Homebrew/npm и скачивает аудио с YouTube — оба действия прямо запрещены
[App Review Guidelines](https://developer.apple.com/app-store/review/guidelines/)
(2.4.5 — запрет на скачивание/исполнение стороннего кода и установщиков вне Xcode;
5.2.3 — запрет на скачивание контента с YouTube без разрешения). Распространяется вне
App Store (прямой .app/.zip). Из духа гайдлайнов всё равно соблюдаются: честные
purpose-strings для каждого разрешения, явное согласие перед записью, никакой скрытой
передачи данных.

## CI и тестирование

Тесты делятся на три уровня — от самых быстрых к самым дорогим.

**Логика приложения** — `cd MeetingApp && swift run MeetingAppTests` (секунды).
Проверяет распознавание ссылок на ВКС (включая свои домены), разбор вывода
whisper/yt-dlp/claude, выбор дорожек записи встречи, подбор модели, переходы
стадий и переезд на единую папку данных. Это обычная программа, а не XCTest:
без Xcode XCTest недоступен, а `swift run` работает на голых Command Line Tools.
Ради тестов чистая логика вынесена в отдельный модуль `MeetingCore` — исполняемую
цель импортировать нельзя, библиотеку можно.

**Скрипты** — `./scripts/tests/run_tests.sh` (секунды) и `--full` (минута).
Быстрые проверяют сшивку дорожек в диалог (порядок реплик, подписи, отброс эха
из колонок) и удаление компонентов вхолостую. Медленные гоняют настоящий
whisper на синтетической речи из `say` и проверяют, что системный звук
подписан «Собеседники», а микрофон — «Я».

**Живая система** — [CHECKLIST.md](CHECKLIST.md). Запись экрана и микрофона,
разрешения macOS, всплывающее облако, строка меню, Notion и Заметки: всё это
проверяется руками на тестовой сборке перед переносом в рабочую.

`.github/workflows/build.yml` на каждый push в `main` и `dev` собирает проект и
гоняет первые два уровня. Медленные тесты в CI не запускаются: им нужна модель
whisper весом в гигабайты.

Релизная сборка (`build_app.sh`) запускается вручную, автодеплоя нет.

Ручная проверка идёт на тестовой сборке (`./build_app.sh --test`) с её собственной
папкой данных, так что рабочая история обработки при проверках не страдает.
